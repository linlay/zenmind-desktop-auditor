# Bridge Lab 验收指南

## 一键检查

导入安装 ZIP 后，在主工作区打开应用，点击“一键测试”。按顺序检查宿主 SDK、后端健康、环境存在性、后端配置及 HTTP/WS 回声，再分别检查页面和后端的只读接口。详情参数只能来自本轮同一入口的真实列表；空列表使下游项目显示条件不足，不使用占位 ID。

每项最多 12 秒，可停止当前等待和后续检查。宿主不支持取消的读取可能仍完成，但迟到结果不更新当前数据或报告。每轮独立统计；模型、原生窗口、Copilot 控制、历史预览和预留接口不会自动调用。原有前端/后端自检入口保留，其中前端自检可检测仍为 stub 的预留方法。

状态区分通过、失败、条件不足、取消、需手动和预留。原生打开/复制/通知等回执只记待观察，必须人工确认实际效果。连接器按 CLI 退出码或 MCP isError 判定业务状态。空列表是合法查询结果，不能证明下游能力成功。

## 报告

默认 JSON 仅导出诊断状态、方法、耗时、错误码及版本指纹，不包括请求、业务结果、事件或产物正文。勾选“报告包含脱敏详情”才附带这些内容；常见凭据遮盖不等于业务内容匿名化。报告包含本轮未调用的项目及 executed 标识。

## 手动流程

1. 配置测试 Agent，执行聊天或结构化任务，点击“查看本次对话历史”或“查看执行对话历史”，核对只读弹窗展示正确 Chat。方法卡片也允许填写实际历史 Chat ID。
2. 在原生能力卡片打开、关闭 Copilot，重复调用核对幂等性、原会话保留及后台 Run 不被停止；禁用 Copilot、后台应用和独立窗口分别核对错误。
3. 生成实际发布产物，从返回清单选择精确 Chat/Run/Artifact；翻页只能使用返回游标，重复游标和迟到响应不得覆盖新清单。
4. 验证元数据和文本；完整 UTF-8 文本可填入 execute。超出请求上限时明确拒绝，不截断正文，也不自动调用模型。
5. 按实际 adapter 验证 CLI/MCP 成功和业务失败。

## 自动与跨平台验证

先用当前 Desktop checkout 构建，再运行 npm test 和 npm run smoke -- --desktop-repo /path/to/desktop。Node 测试覆盖协议和状态边界；Electron smoke 使用隔离 profile、真实 Gateway/SDK 和受控业务响应，不调用真实账号或模型。

macOS 与 Windows 分别人工检查导入、启动、明暗主题、后端连接、历史弹窗、Copilot、原生对话框和麦克风权限。ZIP target:any，包内无原生依赖；本机检查通过不代表另一平台已验收。
